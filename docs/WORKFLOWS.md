# 常用操作指南

## 给用户分享订阅

1. 在“用户管理”找到目标用户，打开“更多操作 → 分享用户”。先确认弹窗中的用户名。
2. 选择接收端的格式。默认 Clash/Mihomo；“自动识别”为普通订阅链接；JSON 为 sing-box JSON 订阅；sing-box 为扫描导入 URI。
3. 扫描当前二维码，或点“复制当前链接”后粘贴到代理客户端。二维码、文本框和复制按钮始终对应同一个选项。
4. 只想分享一个节点时切到“链接”，再选择节点。单节点链接不等于完整订阅。

没有订阅地址时先到“设置”配置公开订阅地址。读取失败时重试，不分享空数据。长链接不生成二维码时仍可复制导入。

“暂停访问”停用该用户，不删除用户；“恢复访问”重新启用。“撤销旧凭据”需要确认，会更新协议登录凭据，旧节点需要重新导入；它不等于撤销或更换订阅 URL。订阅链接含访问标识，不应贴到公开讨论中。

## 配置 DNS 解锁或分流

1. 到“DNS”添加解析服务器，填写服务商明确支持的 UDP/TCP/加密协议、地址和端口。不要把 DNS 服务器当成流量出口节点。
2. 到“路由列表 → 规则目录”添加所需域名规则集。也可以维护本地/远程规则集。
3. 在“DNS 分流”选择规则集或域名条件，并指定步骤 1 的解析服务器；只有需要限定用户或入站时才设置这些条件。
4. 保存后使用“DNS 命中诊断”输入域名，确认命中的解析服务器。诊断是运行态规则模拟，不是真实 DNS 网络查询，也不能证明客户端 DNS 一定经过这台服务器。
5. 在实际客户端验证解析和播放，并检查客户端网关是否接管所需 TCP/UDP、是否把域名而非预先解析的 IP 交给服务端。

“DNS 分流”决定谁解析域名；“流量规则”决定连接从哪个出口发送。单纯 DNS 解锁通常不需要为每个流媒体域名再加一条 `route → direct`；识别域名和接管 DNS 等系统动作也不等于 DNS 服务器选择。

## 保存失败时怎么处理

1. 保存会先调用预检，再提交实际保存；应处理预检中的具体字段或引用错误，而不是反复点保存。
2. 核心下载规则集、初始化 DNS 或启动失败时，从“健康与诊断”和日志查看第一条错误。“启动冷却中”通常只是后续重试保护，不是根因。
3. 面板有失败恢复机制，但浏览器超时不意味着服务器必定没写入。先刷新状态、确认实际配置，再决定是否重试。
4. 前端不会因为重复 POST 自动取消前一个保存，也不会自动重试写操作；这不意味着重复提交变成安全操作。

## 在远端服务器新建入站

1. 进入“服务器集合 → 远程新建入站”，从空白表单选择协议及协议参数。
2. 选择一台或多台在线目标服务器，分别确认监听端口和该目标机自己的 TLS 配置。名称默认按服务器与协议自动填充，例如 `la-http`、`tk-hy2`；默认名称同名时自动增加序号，也可逐台手动编辑。预检和创建使用填写的名称；空名称、目标机已有名称或本批次重复名称会阻止提交。
3. 每台目标机使用自己的域名、证书和用户认证信息，需要的服务端密钥在目标机独立生成。目标机自动关联全部已有本地用户，并保留账号启用/禁用状态；至少需要一个启用用户。
4. 点击“校验全部目标”，确认每台的名称、端口、证书和协议检查通过，再点击“在目标机创建”。全部目标预检通过后才开始逐台创建。
5. 逐台检查创建结果和实际连接。创建失败会停止后续目标；超时后先刷新目标机确认是否已经保存，再决定是否重试。

配置模板与灰度下发功能已移除。服务器集合通过新建协议草稿创建独立入站，聚合订阅仍按原有方式读取各服务器的入站。

## 开发验证

在仓库根目录运行 `sh runNovas.sh`，使用原有 `db/novas.db` 与测试数据，不创建空库替代开发环境。默认面板为 `http://127.0.0.1:2095/app/`，实际端口和路径以现有设置为准。

iMac/macOS 本地开发沿用 `sh runNovas.sh`、原有 `db/novas.db` 和 2095 端口，不依赖 UFW、iptables、nftables、cron 或 systemd；非 Linux 环境跳过 Linux 防火墙/NAT 集成。需要真实特权 Linux 环境的全新安装及 ACME cron 验收，仅在隔离的 GitHub-hosted Linux 作业中执行，不在 Mac 开发机上执行。

单元测试与 mock API 的端到端测试用于验证界面和并发行为，不等于已验证公网 VPS、防火墙、协议握手和服务商的解锁限额。发布与线上更新另行执行。

## 2026-10-13 四项本地实现与验收

以下是本地工作区实现和验证边界，不代表发布版本或 VPS 状态。

### 原生 sing-box MASQUE

- 基于仓库固定的官方 sing-box `v1.15.0-alpha.12` MASQUE 实现，包含两个可复现的 identity observer hooks 和一处自动测速组选择状态的并发保护；三处文件和补丁均有固定哈希与精确重放检查，因此不是逐字节未修改的官方源码，也不是旧 NovaPanel 自研 TUN 实现。
- 客户端 endpoint 使用 HTTP/3、`system: false`、TLS 与用户名/密码。sing-box JSON 输出 `endpoints`。入站可额外开启 Mihomo 密钥认证（ECDSA 证书），Clash 订阅同步生成 `type: masque`、独立用户密钥、固定地址和原生路径；未开启时 Clash 省略此项。不创建自研系统 TUN/NAT，也不伪造通用单节点 URI。
- 同一套 Mihomo 密钥仅支持一个同时在线隧道，多台独立客户端请使用不同用户。原生动态地址避开固定地址；正常保存不换密钥，分享页撤销会同时轮换两种认证。Mihomo 的默认路由通告只被丢弃，不获得路由权限；其他 peer route、forward 和 ICMP 功能仍禁用。证书公钥更换后需刷新订阅。
- `scripts/test-mihomo-masque.sh` 使用官方固定摘要的 Mihomo 1.19.31 验证双客户端 TCP/UDP、地址隔离、认证/撤销及实际导出配置；CI 和发布均必须执行，不能以跳过代替通过。
- 未验证公网客户端互通；不承诺旧客户端兼容或性能提升。

### 异地 WebDAV 备份与恢复演练

- 自动备份默认关闭，仅使用用户配置且严格验证证书的 HTTPS WebDAV 目的地。真实 IAB 已确认默认关闭、未配置目标时远端操作禁用。
- 恢复演练针对独立快照，不接触 live 数据库；校验大小、SHA-256、必要表/字段、完整 SQLite `integrity_check`，并复用正式恢复的 fleet JSON 结构接受规则。演练不启动快照内服务。
- 未连接真实 WebDAV 目的地，未验证外部凭据的实际恢复或服务商行为；不能据此宣称真实恢复成功。

### 持久维护模式与订阅隐藏

- 维护状态持久化；维护期间代理流量保持暂停，管理面板和订阅服务仍可用。订阅隐藏只过滤后续订阅内容，不停止入站、不轮换凭据，也不撤销客户端已导入配置。
- 两项功能已完成本地 UI、单测和 race 回归验证；本地页面显示状态不等同于 VPS 部署。

### 本地验证与发布边界

- 前端：全套 E2E 36 项（含 4 项 operations）、单测 46 项、typecheck、生产构建和 `lint:check` 均通过；隐藏订阅图标已加入 curated CSS。
- Go：固定 Go 1.26.9 的默认全包测试、核心完整 race gate、数据库/服务/订阅/API race、vet、发布所用 staticcheck 均通过。QUIC 集成单独强制检查 PASS；默认构建只跳过依赖 QUIC 的运行态子测试，不跳过订阅结构断言。原生 H3 TCP/UDP、实际限速、错误认证/TLS 拒绝、来源防伪、有效用户撤销与聚合配置启动均有覆盖。
- 自动测速组与原生 endpoint 组合暴露的并发读写已修复；相同启动场景连续 20 次 race 回归通过。漏洞扫描无可达漏洞，另有一个不被调用的模块级发现。Linux amd64 非 CGO 编译检查通过，不等同于正式 musl/Cronet 发布构建或 Linux 公网运行验证。
- 本地沿用原启动脚本、端口 2095 和 `db/novas.db`，未替换测试数据。真实 IAB 验证维护暂停、跨进程重启保留、恢复与正常停服不再误报；最终恢复为非维护且核心运行。
- 本轮没有发布或部署；未使用真实 WebDAV 目的地，也未做公网客户端互通测试。
